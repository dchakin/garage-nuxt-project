# Выход в App Store и Google Play

Цель — чтобы пользователи могли установить «Гараж» из App Store и Google Play, а не только как PWA. Срок не задан, план разбит на этапы, каждый полезен сам по себе.

## Решение: Capacitor, без переписывания

- **Capacitor для обеих платформ.** Одна нативная оболочка вокруг текущего Vue/Nuxt-клиента, один путь нативного push. TWA для Google Play проще, но дала бы третий вариант клиента со своим push, а для iOS всё равно понадобится Capacitor.
- **React Native / Flutter не берём.** Фронтенд пришлось бы писать заново, а для CRUD-трекера с графиками это ничего не даёт. Переписывание оправдано только при появлении offline-first, виджетов, фоновых задач или интеграций вроде OBD/CarPlay — в `TZ.md` этого нет.
- **Веб-версия и PWA остаются.** Тот же SPA-клиент деплоится как сейчас, сторы — дополнительный способ установки.
- Публикация платная при любом стеке: Apple — $99/год, Google — $25 разово.

## Этап 0. Правила для текущей разработки

Действуют уже сейчас, чтобы переход на Capacitor не потребовал переделок:

- Клиент не зависит от SSR: данные грузятся через composables + `$fetch`, без `useFetch`/`useAsyncData` с серверным рендерингом, без `import.meta.server`/`useRequestHeaders` в `pages/`, `components/`, `composables/`. Сейчас код этому уже соответствует.
- Новые API — обычный REST под `/api/*`, без расчёта на то, что страница и API на одном origin (никаких серверных редиректов как части сценария, ответы — JSON).
- Ссылки наружу открываются явно (`target="_blank"`), внутренняя навигация — только через роутер.

Отдельная задача этапа — UX установки PWA: кнопка «Установить» на Android (`beforeinstallprompt`) и подсказка «Поделиться → На экран Домой» на iOS.

## Этап 1. Разделение клиента и API

- Структура монорепы (npm workspaces): `apps/web` — Nuxt-клиент (`ssr: false`, сборка `nuxt generate`), `apps/api` — Nitro + Drizzle + SQLite (текущий `server/`), `packages/shared` — Zod-схемы, типы, утилиты (текущий `shared/`).
- Базовый URL API в клиенте — из runtime config (`NUXT_PUBLIC_API_BASE`): для веба относительный, для мобильной сборки — абсолютный адрес прода.
- Авторизация: к cookie-сессии `nuxt-auth-utils` добавить токены (access + refresh, `Authorization: Bearer`) для мобильного клиента. Cookie из WebView с origin `capacitor://localhost` / `https://localhost` ненадёжны. `requireUserSession` заменить общим хелпером, понимающим оба способа.
- CORS на API для origin'ов Capacitor.
- Docker/деплой: образ собирает оба приложения, `deploy.yml` и `docker-compose.yml` обновить вместе с README.

## Этап 2. Capacitor

- `apps/mobile` (или `apps/web` с `capacitor.config.ts`): `@capacitor/ios`, `@capacitor/android`, `webDir` — результат `nuxt generate`. Клиент **встроен в бандл** — открывать в WebView адрес прод-сервера нельзя, Apple это отклоняет (guideline 4.2).
- Нативные плагины: `push-notifications`, `splash-screen`, `status-bar`, `haptics`, `app` (кнопка «Назад» на Android, deep links), `network` (экран «Нет соединения» вместо белого экрана).
- Доводка под нативное ощущение: safe area и вырезы, отключить выделение текста и «резиновый» скролл всей страницы, без браузерных артефактов.
- Push: в `push_subscriptions` поле `platform` (`web` | `fcm`), в `server/utils/push.ts` — отправка по каналам: `web-push` для PWA, FCM (Firebase Admin SDK) для Android и iOS (через APNs-ключ в Firebase). Дедупликация через `reminder_notifications` не меняется.
- Определение платформы в клиенте (`Capacitor.isNativePlatform()`): `usePush` выбирает Web Push или нативную регистрацию, PWA-сервис-воркер в нативной сборке не регистрируется.
- CI: Android собирается на обычном раннере, iOS — на macOS-раннере GitHub Actions или в Codemagic. Подпись — сертификаты и keystore в секретах.

## Этап 3. Требования сторов

- **Удаление аккаунта внутри приложения** — обязательно для Apple (5.1.1(v)). Сейчас такого эндпоинта нет: нужен `DELETE /api/auth/account` с каскадом по машинам, где пользователь владелец.
- Политика конфиденциальности по публичной ссылке; анкеты App Privacy (Apple) и Data safety (Google).
- Google Play: новый личный аккаунт разработчика сначала проходит закрытое тестирование — не меньше 12 тестировщиков в течение 14 дней. Тестировщиков найти заранее.
- При появлении входа через сторонние сервисы (Google, VK и т. п.) Apple потребует и Sign in with Apple.
- Скриншоты, иконки, описание на русском для карточек приложения.

## Риски

- **Оплата аккаунтов разработчика из РФ.** Apple не принимает российские карты — нужна иностранная карта или юрлицо. Проверить до начала этапов 1–2.
- **Отклонение на ревью Apple** за «сайт в обёртке». Снижается нативными плагинами и доводкой этапа 2; отклонение приходит с причиной, исправляется и отправляется повторно.
- **Доступность FCM/APNs** для пользователей в РФ — проверить доставку на реальных устройствах; Web Push в PWA остаётся запасным каналом.
