# Как вести редизайн по PRD

Порядок работы по `docs/prd-implement-redesign-from-garage-pen.md`: что делаем вручную, что отдаём Ralph, как экономить токены.

## Подход

Гибрид: фундамент делаем интерактивно, типовые задачи (API, экраны) отдаём Ralph.

- **Одна большая сессия не подходит.** Контекст быстро заполняется, качество падает, и каждое сообщение заново отправляет всю историю.
- **Workflow (ultracode) не подходит.** Он нужен для параллельной однотипной работы (аудиты, миграции), а здесь задачи последовательные и зависят друг от друга. В середине прогона вмешаться нельзя, и это дорого. Его можно применить только для финального аудита «экраны против макета».
- **Ralph подходит**: свежий процесс на Sonnet под каждый issue, лимиты бюджета, отдельное ревью. Но сначала нужно снять блокеры (см. ниже).

## Блокеры перед запуском Ralph

- [ ] Нет e2e-инфраструктуры: нет `playwright.config` и скрипта `test:e2e`. `ralph/check.sh` пропускает этот шаг (ссылается на #27, но такого issue в репозитории нет). Без скриншотов ревью UI не работает.
- [x] Ralph не видит макет: он запускается с `--strict-mcp-config`, без Pencil MCP, а `.pen` зашифрован. Нужно экспортировать фреймы в PNG (`design/export/`) и ссылаться на них в issue. → 72 PNG в `design/export/` (экраны 2x, страницы дизайн-системы и сценарии 1x; `08 · UX-аудит` и логотипы не выгружены).
- [x] В PRD нет фаз. Скилл `issues` ожидает план с фазами и чекбоксами, а Ralph выбирает задачи по номеру этапа в milestone. → `docs/plans/redesign.md`, этапы названы `Этап N` под `pick-issue.mjs`.

## Шаги

- [x] **1. План с фазами.** Разбить PRD на фазы и задачи в `docs/plans/redesign.md`. В каждой задаче указать файлы, контракт, критерии готовности и имена фреймов. Кто: Claude в plan mode, модель Opus, новая сессия.
- [x] **2. Экспорт макета.** Выгрузить нужные фреймы `design/garage.pen` в PNG в `design/export/` через Pencil MCP. Имена файлов — код экрана до « · »: `Б1.png`, `Т1.png`, `Сценарий-2.png`, страницы дизайн-системы — `01.png` … `07.png`, `09.png` (на них ссылаются задачи плана).
- [x] **3. Issues.** Через `/issues` создать milestones `Этап N: …` и issues по `docs/plans/redesign.md`. Задачи с меткой `decision` (фундамент) Ralph пропускает. → milestones «Этап 1…11», issues #29–#77, номера проставлены в `redesign.md`.
- [ ] **4. Фундамент** (интерактивно, Opus, каждая задача в новой сессии, контракты записываются в `docs/plans/conventions.md`):
  - [x] e2e на Playwright: конфиг, скрипт `test:e2e`, скриншоты 390 px в светлой и тёмной теме → #29; тёмные скриншоты включаются в задаче темы (#32, `THEMES` в `snap.ts`)
  - [ ] цветовые токены и темы (светлая, тёмная, системная), без вспышки при загрузке
  - [ ] шрифты Onest и JetBrains Mono со своего origin, иконки Lucide
  - [ ] функции форматирования дат, сумм и пробега с unit-тестами
  - [ ] базовые компоненты дизайн-системы
  - [ ] AppBar, TabBar, маршруты и запоминание последней открытой машины
- [ ] **5. API-задачи через Ralph** (Sonnet): этапы 3–5 плана (автор записи, `reminderId`, пробег, массовое создание напоминаний, аналитика, участники, категории, аккаунт, сброс пароля). От фундамента не зависят, можно запускать параллельно с шагом 4. Запуск: `bash ralph/ralph.sh 6`.
- [ ] **6. Экраны через Ralph** (этапы 6–11) пачками по 3–5 issue, только после закрытия этапов 1–2. Между пачками смотреть PR и при необходимости править `conventions.md`.
- [ ] **7. Финал** (интерактивно): проверка в Playwright MCP, финальный аудит против макета, обновление документации (`TZ.md`, `README.md`, `CLAUDE.md`, `conventions.md`, `.env.example`).

## Экономия токенов

- [ ] Одна задача — одна сессия: начинать с `/clear` или нового `claude`. Если ошибка повторилась дважды, лучше `/clear` и более точный промпт, чем третья правка в том же контексте.
- [ ] Модель по задаче: Opus для планирования и фундамента, Sonnet (`/model sonnet`) для типовых экранов и правок. Для простых задач понижать `/effort`.
- [ ] Точные ссылки в промптах: «сделай `AppBar` по `design/export/B1.png`, контракт в `conventions.md`», а не «сделай шапку».
- [ ] Отключить в `/mcp` серверы, которые не нужны (Claude in Chrome, Claude Docs). Pencil включать только на шаге 2.
- [ ] Следить за расходом через `/usage`.
- [ ] У Ralph явно задавать общий бюджет: по умолчанию `RALPH_TOTAL_BUDGET=15` USD на запуск, этого хватает примерно на 4–5 задач.
