# Планы фич

Долговременная память проекта между задачами. `TZ.md` — что строим и зачем, GitHub issues — отдельные задачи, а эти файлы — решения и договорённости, которые одна задача создаёт, а следующие используют.

| Файл | Что внутри |
|---|---|
| `conventions.md` | Общие технические договорённости для всех этапов: тесты, форматирование, структура |
| `stage-1-quick-wins.md` | Этап 1 · Быстрые победы (#26, #27, #1–#9) |
| `stage-2-navigation.md` | Этап 2 · Навигация и Обзор (#10–#17) |
| `stage-3-reminders.md` | Этап 3 · Замкнутый цикл напоминаний (#18–#22) |
| `stage-4-expenses.md` | Этап 4 · Расходы (#23–#25) |

## Правила

- Разделы **«Решения»** и **«Контракты»** обновляются в том же коммите, где решение принято или контракт создан. Формат строки: `- (#N) что решили / что создали — путь, сигнатура`.
- Только то, что понадобится следующим задачам. Пересказ сделанного — в коммитах и PR, не здесь.
- Если решение меняется — исправить строку, а не дописывать противоречащую.
- Файл этапа держать коротким (до ~120 строк): его целиком читает каждая итерация Ralph loop.
