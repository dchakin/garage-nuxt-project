# Правки макета `design/garage.pen` после UX-аудита v2

Аудит всех экранов (А–И, Т1–Т8, сценарии 1–5) нашёл логические несостыковки и пропущенные состояния. Правки разбиты на 18 самодостаточных пунктов: одна сессия — один пункт. От `TZ.md` можно отступать, если так удобнее пользователю (такие отступления помечены **«отступление от ТЗ»** — их нужно перенести в блок решений фрейма `08 · UX-аудит` в пункте 18).

## Как работать с пунктом

Команда: «приступи к пункту №X».

1. Прочитай раздел «Общие правила» и **только** пункт X. Остальные пункты не делай, даже если видишь проблему: запиши её в «Заметки» внизу.
2. Проверь «Зависит от»: если пункт-зависимость не отмечен ✅ в таблице статусов, скажи об этом и спроси, продолжать ли.
3. Выполни шаги, проверь результат по «Готово, когда».
4. Отметь пункт ✅ в таблице статусов и допиши одну строку «что сделано / новые id экранов». Коммит — только если пользователь попросил (скилл `git-commit`).

## Общие правила

### Инструменты

- Макет правится только через Pencil MCP (`mcp__pencil__execute`); файл зашифрован, читать его как текст нельзя.
- Перед первым `execute` в сессии прочитай `mcp__pencil__read_skill({path: "execute.md"})`. Если создаёшь новые экраны или узлы, прочитай ещё `pen-schema.md` и `guide/components.md`.
- `filePath`: `C:\web\projects\garage-nuxt-project\design\garage.pen`.
- Ошибку `execute` исправляй через `edits` + `editId`, а не повторной отправкой кода.
- Не удаляй и не пересоздавай готовые экраны: меняй существующие узлы. Новый экран делай через `Copy` ближайшего похожего.
- Правило из `design/README.md`: экраны собираются только из компонентов (`reusable`) и токенов (`$text`, `$danger`, …). Хардкод цветов запрещён.

### Как устроены экраны

- Экран — фрейм верхнего уровня 390 px, `layout: vertical`. Обычно внутри: `Status Bar` (ref `jIDDL`) → `App Bar` (ref `L6bOFn` AppBar/Car или `PwA1Q` AppBar/Back) → `Content` → `Tab Bar` (ref `B6iA2w`).
- Экран со шторкой: `Behind` (фрейм с копией экрана-подложки) → `Scrim` → `Sheet` (ref `vimSL`). Тело шторки (`DrVcw`) в экземпляре **заменено** целиком, поэтому дети тела — обычные узлы со своими id. Детали самого компонента адресуются путём `<sheetId>/<childId>`: заголовок — `/dRtZf`, текст кнопки — `/uJyFB/Jtzzo`.
- Toast (ref `U9ka6`: `Q8sGUz` — сообщение, `WllLe` — «Отменить») лежит прямо в экране с `layoutPosition: absolute`, x 16, примерно на 64 px выше Tab Bar.
- Чтобы сменить подложку шторки: удали детей `Behind`, скопируй (`Copy`) детей нужного экрана в `Behind` и выставь `Behind.height` равной высоте того экрана.
- Внутри экземпляров узлы адресуются как `instanceId/childId`. Чтобы найти их, читай с `{resolveInstances: true}`:

```js
Get(
  '<screenId>',
  (n, c) => {
    if (c.depth > 5) {
      c.skipChildren()
      return
    }
    Print(
      '  '.repeat(c.depth),
      n.id,
      n.type,
      n.name,
      n.type === 'text' ? n.content : '',
      n.enabled === false ? 'OFF' : '',
    )
  },
  { resolveInstances: true },
)
```

### Глобальная замена текста (шаблон)

Меняет текст во всех экранах, включая экземпляры компонентов, тёмную тему и сценарии:

```js
const pairs = [['было', 'стало']]
let count = 0
Get(
  (n) => {
    if (n.type !== 'text' || typeof n.content !== 'string') return
    let t = n.content
    for (const [a, b] of pairs) t = t.split(a).join(b)
    if (t !== n.content) {
      Update(n.id, { content: t })
      count++
    }
  },
  { resolveInstances: true },
)
Print('заменено', count)
```

Перед заменой выведи список совпадений (корневой фрейм + id) и убедись, что лишнее не задето: страницы `04 · Иконки`, `06 · Компоненты` и т. п. меняй, только если это демо тех же данных.
