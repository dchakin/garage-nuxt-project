# PRD: Редизайн «Гаража» по макету `design/garage.pen`

**Дата**: 2026-10-10 (адаптирован под аудит v2 — 2026-10-12)
**Статус**: Draft

## Цель

Сделать частые действия быстрыми, а состояние машины — понятным с первого экрана. Сейчас добавить трату — это 5+ шагов, закрыть просроченное напоминание нельзя, кнопки удаления легко нажать случайно, интерфейс собран из дефолтных стилей. Новый интерфейс строится на дизайн-системе из макета (тёплая палитра, Onest, Lucide, тёмная тема) и закрывает пункты 1–15 UX-аудита (фрейм «08 · UX-аудит и изменения логики»), а также 16–17.

Аудит v2 (`docs/plans/design-ux-fixes.md`, все 18 пунктов ✅) довёл макет до согласованного состояния: единые эталонные данные, новые состояния и экраны (А7–А9, Б7, В7, Д4, Е3, Е4, Ж3, З3, З4, И8–И10) и пять осознанных **отступлений от `TZ.md`** (блок «Решения» во фрейме `08`):

1. уменьшение пробега — после явного подтверждения;
2. восстановление пароля по email;
3. добавление участника сразу, без приглашения;
4. свои категории можно переименовывать и удалять;
5. удаление аккаунта.

Источник правды по текстам и цифрам — экраны макета и раздел «Эталонные данные» в `design-ux-fixes.md`.

## Пользовательские сценарии

**Обзор и записи**

- Пользователь открывает приложение → попадает на «Обзор» последней открытой машины: пробег, «Требует внимания» (до 3 напоминаний с остатком, ссылка «Все сроки»), расходы месяца, последние записи (Б1).
- Пользователь нажимает «＋» в центре нижней панели на любом экране машины → открывается шторка новой записи. Тип выбирается одним тапом, пробег и дата уже подставлены, сумма крупная, «0» — подсказка, а не значение. Запись сохраняется за 3–4 тапа (Д1, сценарий 2).
- Пользователь вводит пробег меньше текущего при дате «сегодня» → ошибка у поля «Похоже на опечатку», «Сохранить» неактивна (Д3). Если дата в прошлом, это не ошибка: пробег сверяется с соседними по дате записями, расхождение — предупреждение.
- Пользователь нажимает на строку записи в «Журнале» или на «Обзоре» → шторка Д4: все поля, категория и место, подпись «Добавил <имя> · <дата>». «Удалить запись» удаляет сразу, без диалога. Запись пропадает, итоги месяца и года пересчитываются, 5 с висит toast «Запись удалена · Отменить». «Отменить» возвращает запись, и на сервер ничего не уходит (В7).
- Пользователь листает журнал → записи сгруппированы по месяцам с суммой месяца; фильтрует чипами типов и поиском; при сортировке по пробегу группировки нет (В1–В3).

**Напоминания и пробег**

- Пользователь нажимает «Сделал» на просроченном напоминании → шторка «Запись: <название напоминания>» с выбранным напоминанием (Д2). После сохранения появляется запись, срок пересчитывается, toast «Срок сдвинут: следующая замена на 97 450 км», счётчик на вкладке уменьшается (сценарий 3).
- Пользователь создаёт напоминание из шаблона (масло, ОСАГО, ТО, ГРМ, шины) или своё: «каждые N км или M мес», «Последний раз» подставляется из журнала. Предпросмотр считает от последнего раза; если срок уже прошёл — Alert «Срок уже прошёл», и напоминание сразу попадёт в «Требует внимания» (Е1, Е2).
- Пользователь выбирает шаблон, который уже создан → Alert «<Название> уже есть» с кнопками «Открыть «<Название>»» и «Всё равно создать ещё одно». Созданные шаблоны помечены галочкой (Е3).
- Пользователь тапает по карточке напоминания → шторка Е4 «Изменить напоминание»: название, интервалы, «Последний раз», переключатель «Напоминать» (выключенное не шлёт push и не учитывается в счётчике), предпросмотр «Если включить: …». «Удалить напоминание» удаляет сразу, без диалога, с toast «Отменить» (И3).
- Пользователь нажимает «Обновить» на карточке пробега → шторка с полем и кнопками +100/+500/+1 000 (Б5, Б6, сценарий 4). Кнопки прибавляют к прежнему пробегу («Было …»), а не к введённому числу. Блок «Изменится N напоминаний» появляется, только если у кого-то меняется остаток или статус. «Пришлём push» обещается, только если статус переходит в «скоро» или «просрочено». Пробег сохраняется без создания записи.
- Пользователь вводит пробег меньше прежнего → Б7: ошибка «Меньше прежнего на N км», кнопка «Исправить на X км» и «Вернуть Y». После подтверждения пробег уменьшается, напоминания пересчитываются от нового числа.

**Первый запуск и вход**

- Новый пользователь после регистрации проходит мастер из 2 шагов (А3–А6, сценарий 1).
  - Шаг 1 — машина: обязательны марка, модель, пробег; год и госномер необязательны.
  - Шаг 2 — шаблоны напоминаний. По умолчанию срок отсчитывается от сегодня. Можно указать, когда меняли («Указать, когда меняли»). Для ОСАГО вводится «Полис действует до». Кнопка «Назад» возвращает на шаг 1.
  - На выходе — «Обзор» с плашкой «Создали N напоминаний. Включите push…» и кнопкой «Включить push» прямо на ней (А6).
- Пользователь ошибается при входе → ошибка «Неверный email или пароль» только в Alert, поля не подсвечиваются (А2).
- Пользователь нажимает «Забыли пароль?» → вводит email (А7) → видит «Проверьте почту»: ссылка действует 1 час, кнопка «Открыть почту», повторная отправка с таймером (А8) → по ссылке задаёт новый пароль, минимум 6 символов, и сразу входит (А9).

**Машина, участники, категории**

- Пользователь открывает переключатель машин (Б4) → там же строка «Настройки <машина>».
- Владелец открывает настройки машины (З2): правит данные. Пробег — строка, ведущая в шторку Б5, а не поле. Строка «Категории» со счётчиком ведёт в З3. Ниже — участники с ролями.
- Владелец нажимает «Добавить» → шторка «Добавить участника» с объяснением прав (И1). Участник появляется сразу.
  - Email не зарегистрирован → ошибка у поля и кнопка «Поделиться ссылкой на приложение» (И8).
  - Человек уже участник → «<Имя> уже участник этой машины» (И9).
  - «Добавить» неактивна, пока email не изменён.
- Владелец убирает участника; удаляет машину через диалог с перечнем последствий: сколько записей и напоминаний удалится, кто из участников потеряет доступ (И2).
- Участник открывает настройки чужой машины → З4: Alert «Данные машины меняет владелец — <имя>», данные только для чтения, пробег обновлять можно, «Покинуть машину…» с подтверждением. После выхода машина пропадает из его списка, записи остаются у владельца.
- Пользователь открывает «Категории» (З3). Стандартные общие для всех машин и только читаются, у каждой — число записей этой машины. Свои — только для этой машины: их можно добавить, переименовать и удалить, записи удалённой уходят в «Прочее».

**Расходы**

- Пользователь открывает «Расходы» (Ж1): Segmented «Месяц / Год / Всё время» и переключатель «‹ 2026 год ›». В будущее листать нельзя. На экране:
  - сумма за период и «в среднем N ₽ в месяц»;
  - стоимость километра и средняя запись;
  - «Больше всего в <месяце> · <сумма>»;
  - график по месяцам и разбивка по категориям с долями, сумма долей = 100 %.
- У машины нет ни одной траты → Ж2 без Segmented. В выбранном периоде трат нет, а в других есть → Ж3: «В июле трат не было», ближайшие траты до и после и кнопка «К июню».

**Профиль и аккаунт**

- Пользователь в профиле (З1) видит блок «Аккаунт»: имя (можно изменить), email (только чтение), «Сменить пароль». Ещё там push-уведомления, тема («Как в системе / Светлая / Тёмная»), список машин и «Выйти».
- «Удалить аккаунт…» → диалог с перечнем последствий (И10): удалятся машины, где пользователь владелец, со всеми записями и напоминаниями, а из чужих машин он просто выйдет. После подтверждения — выход на экран входа.

**Ошибки и сеть**

- Пользователь теряет сеть → видит плашку «Нет соединения» и последние загруженные данные (Б3); при ошибке загрузки — экран ошибки с повтором (В6).
- Пользователь открывает чужую или несуществующую машину, ловит ошибку сервера или истёкшую сессию → экраны 403 / 404 / 500 / «Сессия истекла» (И4–И7). 403 покрывает и случай «вас убрали из участников». После повторного входа из И7 пользователь возвращается на маршрут, где был.

## В скоупе

**Дизайн-система (фреймы 01–07)**

- Цветовые токены из макета со значениями для светлой и тёмной темы; все цвета в UI берутся только из токенов.
- Шрифты: Onest для всего интерфейса (табличные цифры), JetBrains Mono для госномера и VIN.
- Иконки Lucide вместо эмодзи. Иконка `plus` — только на кнопках добавления.
- Новый логотип (арка гаража + машина анфас) в `logo.svg`; PWA-иконки пересобраны из него.
- Компоненты макета:
  - кнопки (Primary/Secondary/Tonal/Danger/Text), IconButton;
  - поля (Field, Textarea, Amount, Search), Chip (в т. ч. с иконкой `check`), Segmented, Toggle, TypeOption;
  - бейджи типов и статусов, Avatar, Plate, Spinner, Progress;
  - строки: Entry, Setting, KeyValue (только чтение), Car, Toggle — внутри Card, с разделителями;
  - заголовки Month и Section;
  - Card, Card/Reminder;
  - графики Column, CategoryBar, MiniBars; скелетоны;
  - AppBar (Car, Back), TabBar, Sheet, Dialog, Toast, Alert (error/warning/success/info), EmptyState, Bridge/Reminder, Disclosure;
  - переключатель периода «‹ период ›».

**Навигация и экраны**

- Нижняя панель из 5 слотов: Обзор · Журнал · ＋ · Напоминания · Расходы. Счётчик на «Напоминаниях» = просроченные + скорые среди **включённых** напоминаний. Если таких нет, бейджа нет.
- Отдельные маршруты для «Обзора», «Журнала», «Напоминаний», «Расходов», настроек машины, «Категорий» и «Профиля»; маршруты восстановления пароля.
- Шапка с переключателем машин и строкой «Настройки <машина>» (Б4); последняя открытая машина запоминается на устройстве, и при входе открывается её «Обзор».
- Экраны А1–А9, Б1–Б7, В1–В7, Г1–Г3, Д1–Д4, Е1–Е4, Ж1–Ж3, З1–З4, И1–И10 с состояниями из макета: загрузка (скелетон), пусто, ошибка, нет сети.
- Тёмная тема на всех экранах (эталон — Т1–Т8), переключатель в профиле, выбор сохраняется; `theme-color` соответствует теме.
- Блок push убран со списка машин в профиль; все прежние состояния push сохраняются; дополнительно кнопка «Включить push» на «Обзоре» после мастера (А6).

**Форматирование и статусы (п. 8–9)**

- Единые форматы: даты «12 сент», суммы «6 800 ₽», пробег «87 450 км», неразрывный пробел в числах.
- Строка записи из двух строк: что сделали + сумма; дата · пробег · место.
- Статус напоминания = цвет + иконка + слово, с остатком словами («Через 750 км», «Просрочено на 39 дней», «≈ 8 мес») и полосой прогресса; цвета статуса одинаковы во всех местах, где он показан.

**Формы (п. 1, 5, 6, 12)**

- Форма записи в шторке: тип → «что сделали» с подсказками из прошлых записей → сумма → пробег/дата → остальное свёрнуто. Обязательны только тип и дата; пустая сумма — запись без расходов. Пробег по умолчанию — текущий пробег машины, дата — сегодня. Правило пробега — как в сценарии Д3.
- Шторка просмотра/правки записи (Д4) с автором записи и удалением.
- Форма напоминания: шаблоны, интервалы «N км или M мес», «Последний раз» из журнала, предпросмотр от последнего раза. Отдельные состояния: «срок уже прошёл» (Е1) и дубликат (Е3). Форма правки (Е4) — с переключателем «Напоминать» и удалением.
- Ошибки валидации показываются у поля с причиной (Д3, И8, И9); неактивная основная кнопка, пока ошибка не исправлена. Ошибки сервера — Alert; после успешного действия — Toast.
- Отложенное удаление (запись, напоминание) — без диалога, с toast «Отменить». Диалог подтверждения — только для необратимого: машина, аккаунт, выход из машины, уменьшение пробега (Б7).

**Изменения API и данных**

Записи и напоминания:

- `POST /api/cars/[id]/entries` принимает необязательный `reminderId`. Сервер пересчитывает срок напоминания от новой записи и сбрасывает отметки об отправленных push по нему.
- Записи в ответах API содержат автора (`author: { id, name }`) — для подписи «Добавил …» в Д4.
- Тип срабатывания напоминания вычисляется из заполненных интервалов; клиент его не передаёт, колонка `trigger_type` остаётся в БД.
- Массовое создание напоминаний по шаблонам одним запросом (мастер). Для каждого шаблона можно передать «последний раз» (дата и/или пробег) или прямой срок (ОСАГО: `nextDueDate`); без них отсчёт от сегодня и текущего пробега.
- Выключенные напоминания (`isActive = false`) не участвуют в счётчике и рассылке push.
- Дубликат напоминания определяется на клиенте по названию шаблона; сервер дубли не запрещает («Всё равно создать ещё одно»).

Пробег:

- Отдельный роут обновления пробега доступен владельцу **и участникам**.
- Уменьшение — только с явным флагом подтверждения, иначе 400.
- После обновления — пересчёт статусов и push, как сейчас при новой записи.
- `PATCH /api/cars/[id]` (только владелец) больше не меняет пробег.

Участники:

- Добавление по email сразу, без приглашения (существующий `invite.post.ts`). Тексты ошибок 404 «нет такого пользователя» и 409 «уже участник» — под И8/И9 (**отступление от `TZ.md`**).
- `DELETE /api/cars/[id]/members/[userId]` — убрать участника: только владелец, себя-владельца убрать нельзя.
- `DELETE /api/cars/[id]/members/me` — участник покидает машину; владелец не может (только удалить машину).
- В ответе машины для экрана настроек — имя владельца (Alert З4). Для диалога И2 — число записей и напоминаний машины.

Категории (**отступление от `TZ.md`**):

- Схема: `categories.carId` (null — стандартная, общая для всех), уникальность названия в пределах машины.
- Миграция существующих пользовательских категорий:
  - категория используется одной машиной → привязать к ней;
  - используется несколькими → скопировать для каждой;
  - не используется → удалить.
- `GET /api/cars/[id]/categories` — стандартные + свои с числом записей этой машины.
- Добавление своей категории — к машине.
- `PATCH`/`DELETE` только своих категорий, для любого участника машины. При удалении записи уходят в «Прочее», ссылки из напоминаний обнуляются. Стандартные не меняются.

Аналитика:

- `GET /api/cars/[id]/analytics?period=month|year|all&date=…` (якорь периода: `YYYY-MM` для месяца, `YYYY` для года) возвращает:
  - итог и «в среднем в месяц» (с первого месяца с тратой в периоде);
  - стоимость километра и среднюю запись;
  - самый затратный месяц с суммой;
  - суммы по месяцам и по категориям с долями (сумма долей = 100);
  - есть ли у машины траты вообще (Ж2);
  - ближайшие периоды с тратами до и после выбранного (Ж3).

Аккаунт:

- `PATCH /api/auth/me` — изменить имя.
- `POST /api/auth/password` — сменить пароль: нужен текущий пароль; refresh-токены других устройств отзываются.
- `DELETE /api/auth/account` — удаление аккаунта: машины, где пользователь владелец, удаляются каскадом; из чужих он выходит; push-подписки и токены удаляются (**отступление от `TZ.md`**).
- Сброс пароля (**отступление от `TZ.md`**):
  - `POST /api/auth/password-reset` — запрос по email; ответ одинаковый, даже если email не найден; повторный запрос не чаще раза в 60 с на email;
  - одноразовый токен живёт 1 час и хранится хешированным; письмо со ссылкой;
  - `POST /api/auth/password-reset/confirm` — новый пароль по токену; ответ как у входа, т. е. сразу вход;
  - прежние сессии и refresh-токены после этого недействительны.

Клиент:

- Отложенное удаление записей и напоминаний делается на клиенте. DELETE уходит через 5 с, если не нажали «Отменить». Если уйти со страницы или закрыть вкладку до истечения таймера, удаление выполняется.
- При 401 без возможности refresh — экран «Сессия истекла» (И7); исходный маршрут сохраняется и открывается после входа.

**Документация**

- `TZ.md`: новые роуты; пять отступлений («Решения» фрейма `08`); сброс пароля по email — исключение из «email вне рамок»; экраны.
- `README.md`: env-переменные отправки почты.
- `CLAUDE.md`: архитектура, маршруты, компоненты; устаревший абзац «Reminders/analytics status».

- Мягкое удаление на сервере (`deletedAt`, восстановление).
- Мультивалютность — везде ₽.
- Email-уведомления о напоминаниях (почта только для сброса пароля) и приглашения участников по почте.
- Смена email аккаунта (в профиле email только для чтения).
- Пагинация журнала по месяцам на 300+ записей.
- Нативные сборки Capacitor.
- Десктоп-раскладка сверх адаптации мобильной вёрстки: макет нарисован под 390 px.

## Технические ограничения

- Клиент остаётся SPA и совместимым с Capacitor: без SSR-API, данные — через composables + `$fetch` (`docs/plans/mobile-stores.md`, этап 0).
- Изменения схемы проходят все слои: `schema.ts` → Zod в `packages/shared/schemas` → `types.ts` → новая миграция. Применённые миграции не редактируются.
- Каждый новый роут вызывает `requireAuth`, а роуты с машиной — ещё и `requireCarAccess`. Удаление участника, правка данных и удаление машины дополнительно проверяют роль владельца. Пробег, записи, напоминания и свои категории доступны любому участнику.
- Для отправки писем нужен внешний SMTP/почтовый сервис и новые env-переменные. Без них сброс пароля выключен, а ссылка «Забыли пароль?» не показывается (по аналогии с push без VAPID).
- PWA-иконки генерируются из `public/logo.svg` через `pwa-assets.config.ts`, руками не правятся.
- Тема переключается классом на `<html>` и применяется до первой отрисовки — без вспышки светлой темы.
- Шрифты отдаются со своего origin (PWA, Capacitor), а не с внешнего CDN во время работы.
- Остаток и статус напоминания считаются только через `packages/shared/utils/reminderStatus.ts`, без второй реализации. Через него же — счётчик вкладки, блок «Изменится N напоминаний» в Б5 и предпросмотр в Е1/Е4.
- Лимиты размера: файл ≤ 250 строк, функция ≤ 40 строк. Текущие `cars/[id]/index.vue`, `EntryForm.vue`, `EntryJournal.vue` декомпозируются, а не дописываются.
- Отложенный DELETE должен быть устойчив к закрытию вкладки: нельзя терять удаление и нельзя удалять после нажатия «Отменить».
- Скриншоты e2e — при ширине 390 px, в светлой и тёмной теме; данные e2e-фикстуры совпадают с эталонными данными макета (Toyota Camry, 10 окт 2026), чтобы скриншоты сравнивались с макетом один к одному.
