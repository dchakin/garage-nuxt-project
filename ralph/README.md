# Ralph loop

Автономный цикл, который берёт открытые GitHub issues по очереди и реализует их. Каждая задача — новый процесс `claude -p` с чистым контекстом. Память между задачами хранится в git и в `docs/plans/`, а не в контексте модели.

## Запуск

```bash
bash ralph/ralph.sh      # одна задача
bash ralph/ralph.sh 3    # до трёх задач подряд
touch .ralph/STOP        # остановиться после текущей задачи
```

Перед запуском рабочая копия должна быть чистой: скрипт переключает ветки. После завершения он возвращается на исходную ветку.

Нужны: `claude` (вход выполнен), `gh` (выполнен `gh auth login`), `node`, `npm`, push-доступ к `origin`.

## Что происходит с одной задачей

1. **Выбор.** Первый открытый issue: сначала с меткой `tests`, затем по номеру этапа в milestone, затем по номеру. Пропускаются метки `decision`, `ralph:blocked`, `ralph:in-review`.
2. **Ветка** `ralph/issue-N`: от последнего открытого PR Ralph, если такой есть (цепочка), иначе от `origin/dev`.
3. **Реализация**: Sonnet, `ralph/prompts/implement.md` + текст issue + план этапа + `docs/plans/conventions.md`. Модель пишет код и тесты, обновляет план и коммитит.
4. **Проверки** (`ralph/check.sh`): `npm test`, `typecheck`, `build`. Их запускает скрипт, решение принимается по коду возврата.
5. **Ревью**: отдельный процесс Sonnet с чистым контекстом и доступом только на чтение (`ralph/prompts/review.md`). Возвращает JSON-вердикт `APPROVE` или `CHANGES`.
6. **Итог**:
   - всё зелёное и ревью одобрило → push, PR в `dev` с `Closes #N`, метка `ralph:in-review`;
   - проверки красные или ревью вернуло задачу → следующая попытка получает хвост лога или замечания (до 3 попыток);
   - попытки кончились или модель ответила `BLOCKED:` → комментарий в issue и метка `ralph:blocked`.

## Как мёржить

PR открываются в `dev`, мёржите их вы. Если PR создан поверх ещё не смёрженного PR (об этом есть предупреждение в описании), мёржите по порядку и способом **Create a merge commit**. Squash или rebase задвоят коммиты в следующем PR.

Задачу из `ralph:blocked` можно вернуть в очередь: поправьте issue или план и снимите метку.

## Экономия токенов

| Что | Как |
|---|---|
| Чистый контекст на каждую попытку | Новый процесс `claude -p`, `--no-session-persistence` |
| Модель не ищет задачу сама | Скрипт вставляет в промпт issue и **только** план текущего этапа |
| Нет MCP и скиллов | `--strict-mcp-config`, `--disable-slash-commands` |
| Нет дорогих веток | Запрещены `Agent`, `WebSearch`, `WebFetch` |
| Итог по коду возврата, а не по словам модели | Проверки запускает `check.sh`; в следующую попытку передаются только последние 80 строк лога |
| Жёсткий потолок | `--max-budget-usd` на каждую реализацию и ревью; не больше 3 попыток на задачу |

В конце запуска выводится итоговая стоимость. Подробные логи (stream-json) лежат в `.ralph/logs/<запуск>/`.

## Настройки (переменные окружения)

| Переменная | По умолчанию | |
|---|---|---|
| `RALPH_MODEL` | `sonnet` | Модель для реализации и ревью |
| `RALPH_MAX_ATTEMPTS` | `3` | Попыток на задачу |
| `RALPH_IMPL_BUDGET` | `3` | Лимит в USD на одну попытку реализации |
| `RALPH_REVIEW_BUDGET` | `1` | Лимит в USD на одно ревью |
| `RALPH_BASE` | `dev` | Базовая ветка PR |

## Безопасность

Модель работает в режиме `dontAsk`: разрешено только то, что явно перечислено в `IMPL_TOOLS` в `ralph.sh` (правка файлов, `npm`/`npx` для тестов и сборки, `git add/commit/diff/log`). Запрещены push, смена веток, reset/rebase/merge и `gh`: всё это делает скрипт. Цикл работает прямо на вашей машине, без контейнера, а `npm run` и `npx` могут выполнить любой код из проекта. Поэтому запускайте цикл только на этом репозитории и просматривайте PR перед мёржем.

## Файлы

```
ralph/
  ralph.sh             главный цикл
  check.sh             проверки (можно запускать вручную)
  prompts/implement.md промпт реализации
  prompts/review.md    промпт ревью
  review-schema.json   JSON-схема вердикта ревью
  lib/pick-issue.mjs   выбор следующей задачи
  lib/result.mjs       разбор вывода claude -p
docs/plans/            планы этапов — долговременная память между задачами
.ralph/                логи и STOP-файл (в .gitignore)
```
